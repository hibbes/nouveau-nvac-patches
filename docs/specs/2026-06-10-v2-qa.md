# v2 QA and rework (2026-06-10)

Adversarial review of the v1 series (sent 2026-04-09, three-week soak report
2026-04-26, first external test by Fab Stz on iMac9,1 / MCP79 / 6.12.90 on
2026-06-09) plus a build + checkpatch pass against the 7.0.12 tree. Outcome: a
reworked v2 of the two upstream-bound patches, and 0003 pulled out of the
stable series.

## Findings that forced changes

- **0002 (sor NULL guard) had a real regression.** The v1 early-return called
  `nvif_outp_release()`. That double-releases: the release is owned by the
  commit_tail release loop (`nv50_disp_atomic_commit_core`), so the second call
  hits the `!outp->ior` guard and logs `[RELEASE]` errors, and it detaches the
  OR before the disable flush while the EVO core still references the SOR, which
  on NVAC risks the very core-notifier timeout the series fights. v2 drops the
  release and replaces the silent `return` with `drm_WARN_ON_ONCE()` so the
  underlying state-tracking inconsistency stays visible.
- **0001 (MSI rearm) was over-broad.** v1 flipped the shared `g94_pci_func`,
  which is used by ten chipsets (G94/G96/G98/GT2xx and the MCP77/MCP79/MCP89
  IGPs), while only NVAC was tested. v2 narrows to a dedicated `mcp79_pci_func`
  (device id 0xac only). MCP77/MCP89 are called out as plausible-but-untested.
  Precedent: g92 was split out of the same table for the same reason
  (5112abc6a433).
- **0003 (HPD link-check retry) is not stable material.** It sleeps 100ms under
  `dev->mode_config.mutex` and is a behavioral workaround, not an obviously
  correct fix. Dropped from the Cc:stable series; to be revisited separately
  (and re-validated against the soft_dpms prevention work before any resend).
